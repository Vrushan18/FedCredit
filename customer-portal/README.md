## 🏛️ Overview

The **Customer Portal** represents the public-facing and authenticated retail banking digital experience of the **FedCredit Privacy-Preserving Federated Credit Risk & Intelligent Fraud Alert System**.

Engineered like modern Tier-1 fintech platforms (e.g. HDFC, ICICI, SBI), the customer portal enables consumers to register, log in, browse participating partner banks (Bank A & Bank B), apply for loans, upload KYC documents and biometrics, and track credit review lifecycles in real time.

---

## 🔒 Privacy & Architecture Principles

In strict adherence to the project contract:
1. **Zero Data Centralization:** Customer financial statements, salary proofs, and KYC records are **never** sent to the Head Office. They are transmitted directly to the chosen partner bank port (`POST {bank.api_base_url}/applications`).
2. **Dynamic Bank Discovery:** Bank URLs are **never hardcoded**. They are dynamically fetched from the Head Office via `GET /banks`.
3. **Biometric Privacy:** When a customer uploads a fingerprint image, the portal displays:
   > *"Fingerprint uploaded successfully. Protected identifier will be generated by Bank."*  
   The portal never mentions hashing or internal algorithms.
4. **Information Firewalls:** The customer sees **only** the 5 frozen statuses:
   - `SUBMITTED`
   - `UNDER_REVIEW` (All intermediate states between submission and decision)
   - `APPROVED`
   - `REJECTED`
   - `VERIFICATION_REQUIRED` (UI Label: *"Manual Verification Required"*)  
   The customer never sees ML probabilities, SHAP factors, or fraud scores.
5. **Periodic Polling:** Application tracking (`GET /applications/mine`) and notifications (`GET /notifications`) are polled every **15 seconds**.

## 🚀 Getting Started

### 1. Prerequisites
- Node.js `v18+` or `v20+` (tested on Node v22)
- npm `v9+` or `v10+`

### 2. Environment Configuration
Create a `.env` file from `.env.example`:

```bash
# For local single-machine development
VITE_HEAD_OFFICE_URL=http://localhost:8000/api/v1

# For multi-laptop Tailscale demo (replace with Vrushan's Tailscale IP)
# VITE_HEAD_OFFICE_URL=http://100.x.y.z:8000/api/v1
```

> **Contract Rule:** `VITE_HEAD_OFFICE_URL` is the **only** backend URL in `.env`. Bank URLs are received dynamically from `GET /banks`.

### 3. Start Development Server
```bash
npm install
npm run dev
```

The portal runs on `http://localhost:5173` and binds to all local network adapters (`host: true`), enabling seamless access across your Tailscale Tailnet.

### 4. Build for Production
```bash
npm run build
npm run preview
```

## 📐 Endpoints Integration Matrix

| Step | Action | Method & Target | Auth Token | Payload / Response |
|---|---|---|---|---|
| 1 | Register Customer | `POST /auth/customer/register` (Head Office) | None | `{ name, email, phone, password }` ➔ `201 { customer_id: "CUST-..." }` |
| 2 | Login Customer | `POST /auth/customer/login` (Head Office) | None | `{ email, password }` ➔ `200 { access_token, token_type: "bearer", customer }` |
| 3 | Fetch Online Banks | `GET /banks` (Head Office) | Customer JWT | ➔ `[{ bank_id, name, api_base_url, online }]` |
| 4 | Create Intent | `POST /applications` (Head Office) | Customer JWT | `{ bank_id }` ➔ `201 { application_id: "APP-...", status: "SUBMITTED" }` |
| 5 | Submit Application | `POST {bank.api_base_url}/applications` (Bank A/B) | Customer JWT | `multipart/form-data`: `data` (JSON), `documents` (files), `fingerprint` (image) |
| 6 | Poll Applications | `GET /applications/mine` (Head Office) | Customer JWT | ➔ `[{ application_id, bank_id, status, ... }]` (Polled every 15s) |
| 7 | Application Detail | `GET /applications/{id}` (Head Office) | Customer JWT | ➔ `{ application_id, status, timeline: [...] }` |
| 8 | Poll Notifications | `GET /notifications` (Head Office) | Customer JWT | ➔ `[{ id, type, message, read }]` (Polled every 15s) |

1. **Explain the Architecture:** "I built the Customer Portal (Laptop 4). It interacts with Vrushan's Head Office server for customer authentication, bank directory lookups, and timeline tracking. When a customer submits a loan application, the financial payload and biometrics are dispatched directly to Gopal's Bank A or Nidhi's Bank B."
2. **Explain the Privacy Shield:** "Notice that our portal enforces data residency. Head Office only holds an application reference number and status; it never holds the applicant's salary, existing debt, or KYC documents."
3. **Explain the Biometric Verification:** "The user uploads a sample fingerprint image. We do not store or transmit raw biometrics across institutions. The selected bank converts the fingerprint into an anonymous 64-character HMAC-SHA256 token and immediately purges the raw file."
4. **Demonstrate Bank Offline Handling:** "If Bank A or Bank B goes down, our UI instantly flags the partner bank as offline and disables submission, preventing lost transactions."
